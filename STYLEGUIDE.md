# Xintong Portfolio Style Guide

This document defines the visual and editorial rules for the current portfolio. It is not a redesign brief. It exists to protect and sharpen the existing direction.

## Core Thesis

This site should feel like a digital desk left behind by someone:

- intelligent
- aesthetically disciplined
- genuinely productive
- warm, not performative

It is not a startup landing page.
It is not a generic personal portfolio.
It is not a moodboard.

It should feel placed, not generated.

## Creative Direction

The current style is the right one. Keep these qualities:

- warm paper tones
- desktop / file / archive references
- editorial restraint
- traces of personality
- technical fluency without “developer template” energy

The page should suggest:

- a person who reads, builds, writes, and thinks
- a desk where projects, files, notes, and cultural references naturally coexist

## What This Site Is

Think:

- digital writing desk
- personal archive
- editorial operating system

Do not drift toward:

- SaaS product site
- glossy creator brand page
- maximalist art project
- cute portfolio with too many decorative tricks

## Typography System

Typography carries most of the site's intelligence. The hierarchy should be strict.

### Type Roles

Use only three voices:

1. Display serif
   Use for:
   - hero name
   - section titles
   - selected project titles

   Desired qualities:
   - elegant
   - literary
   - calm
   - assured

   It should feel like an editorial heading, not a costume.

2. Chinese Song-style serif
   Use for:
   - About body copy
   - project descriptions
   - writing content
   - education / experience body text
   - most mixed Chinese-heavy text

   Desired qualities:
   - readable
   - grounded
   - intelligent
   - text-forward

   This is the main reading voice of the site.

3. Mono
   Use for:
   - path-like labels
   - filenames
   - timestamps
   - tiny metadata
   - status fragments
   - system-like annotations

   Desired qualities:
   - precise
   - quiet
   - secondary

   Mono must never dominate the page.

### Type Hierarchy

Desktop:

- Hero display: `72-96px`, `line-height: 0.95-1.0`
- Section title: `42-56px`, `line-height: 1.0-1.08`
- Project title: `30-38px`, `line-height: 1.08-1.14`
- Body text: `16-18px`, `line-height: 1.8-1.95`
- Support text: `13-15px`, `line-height: 1.65-1.8`
- Meta mono: `10-12px`, `line-height: 1.4-1.55`

Mobile:

- Hero display: `44-56px`
- Section title: `30-38px`
- Project title: `26-32px`
- Body text: `15-17px`
- Meta mono: `10-11px`

### Type Rules

- Body text should be darker and slightly larger than typical AI-default portfolios.
- Italics should be rare.
- Use italics as a single accent, not a personality layer.
- Chinese reading text should never feel like default app UI copy.
- Mono should annotate, not headline.
- Avoid overly decorative letterforms in dense reading areas.

## Visual Hierarchy

The user should feel this order:

1. Person
2. Work
3. Method
4. Archive / context
5. Interface detail

This means:

- the page should first communicate who Xintong is
- projects should feel like real work, not placeholders
- UI detail should support the presence of the person, not overshadow it

## Layout Principles

Keep the current structure. Improve only precision and rhythm.

### Hero

The hero is the center of the desk.

Requirements:

- the visual axis must feel stable
- the hero should not feel like marketing
- the objects around it should feel placed, not scattered
- the resume icon and key hero artifacts should feel like intentional desk objects

Do not:

- overfill the hero
- over-center everything into generic symmetry
- turn the hero into a startup banner

### About

About should read like a personal note with intellectual credibility.

Requirements:

- text should feel article-like
- image and metadata should feel related, not disconnected
- avoid both slack emptiness and cramped compression

### Projects

Projects are the main course of the site.

Each project should communicate:

- identity
- output
- process
- taste

The card should feel like a real work artifact on a desk, not a product listing.

### Writing

Writing should feel like reading from a notebook or archive drawer, not a blog CMS.

### Podcast

Podcast should feel like one thread in the same life, not a promotional block.

## Spacing Rhythm

The site should breathe, but not float away.

Use:

- broader spacing between sections
- tighter spacing inside content groups
- tighter rhythm in metadata and project blocks
- slightly more air in hero and about

Good spacing here should feel deliberate, not generous for its own sake.

### Spacing Rule

If a section feels empty, tighten the internal spacing before shrinking the outer padding.

## Color System

The palette is already working. Keep it.

Primary world:

- paper
- cream
- warm gray
- soft ink

Accent roles:

- olive for intelligence, confidence, and structural emphasis
- pink for rare warmth or emotional lift
- soft blue for selected object details only

Rules:

- accents must stay rare
- most of the site should read as paper and ink
- color should support hierarchy, not decorate by default

## Surface Language

The UI should feel object-like, not card-heavy.

Use:

- thin borders
- subtle translucency
- small corner radii
- soft shadows

Do not use:

- large pill shapes by default
- thick cards everywhere
- exaggerated glassmorphism
- soft blob decorations

## Motion

Motion should feel like handling paper and objects on a desk.

Use:

- fades
- slight lifts
- soft staggered entrances
- small spatial adjustments

Do not use:

- bouncy motion
- flashy transitions
- motion that competes with the content

## Interaction Rules

- Important objects should feel clickable without shouting.
- Labels should feel like tags or filenames, not button chrome.
- Modals should appear with confidence and immediacy.
- Navigation should feel anchored, not animated for its own sake.

## Mobile Principles

Mobile should preserve the same personality, not degrade into generic app UI.

Rules:

- keep mobile typography editorial
- preserve project imagery
- reduce wasted vertical emptiness
- keep hero objects legible and intentional
- treat mobile as a compact desk, not a stripped-down fallback

## Anti-Patterns

Avoid these unless explicitly chosen for a concept:

- default sans everywhere
- too much mono
- full pill-shaped labels
- generic startup gradients
- over-rounding
- overexplaining the UI
- decorative clutter
- every section having equal visual intensity
- “nice” but personality-free spacing

## Internal Review Checklist

Before accepting a UI change, ask:

- Does this feel placed or generated?
- Does this make the site feel more like a digital desk?
- Is the typography doing one clear job per text role?
- Is the accent color still rare enough?
- Is the work more visible than the interface?
- Does this feel smarter, calmer, and more authored?

## One-Line Rule

Everything should feel placed, not generated.
